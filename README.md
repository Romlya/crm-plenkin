# CRM ПЛЕНКИН

Рабочее место для учёта лидов, заказов, оплат и прибыли. Автономное приложение:
работает на своём компьютере или сервере, без внешних сервисов и подписок.
Данные — в одном файле на диске, с ежедневными бэкапами.

Дизайн повторяет фирменный стиль [plenkinaokna.ru](https://plenkinaokna.ru):
тёмная тема, золотой акцент, сдержанная типографика. Полностью адаптивно:
десктоп, планшет, телефон (нижняя навигация, карточки вместо таблиц).

---

## Быстрый старт

```bash
node server.js          # http://localhost:7788
# или двойной клик по start.bat (Windows)
```

Зависимостей нет — `npm install` не требуется. Нужен только Node.js 18+.

При первом запуске CRM попросит задать пароль (одна учётная запись — владелец).
Дальше можно загрузить демо-данные одной кнопкой, чтобы посмотреть все разделы.

> Пароли по умолчанию (`owner/plenkin2026`) из старой версии **удалены**:
> первый вход всегда настраивается владельцем.

## Разделы

| Раздел | Возможности |
|---|---|
| **Обзор** | выручка и прибыль за 30 дней, лиды, дебиторка, график 12 месяцев, воронка, «требуют внимания», задачи |
| **Лиды** | канбан с drag&drop и список, источники, оценка, конвертация в заказ одной кнопкой |
| **Заказы** | статусы (новый → замер → материалы → монтаж → выполнен → закрыт), сумма, себестоимость, маржа, срок, прогресс оплаты |
| **Оплаты** | частичные платежи, способы (наличные/карта/перевод/счёт), периоды, автоматический пересчёт |
| **Клиенты** | карточка, LTV, долги, история заказов и оплат |
| **Расходы** | категории, структура, влияние на прибыль |
| **Аналитика** | P&L, динамика, воронка конверсии, источники, услуги, топ клиентов, дебиторка |
| **Настройки** | реквизиты, услуги и цены, источники, категории, интеграция с сайтом, бэкапы, пароль |

Дополнительно: поиск `Ctrl+K`, экспорт CSV (Excel), бэкап JSON, приём заявок с сайта
по ключу `X-API-Key`, доступ с телефона по локальной сети.

### Как считается прибыль

```
Выручка         = поступившие оплаты за период
Себестоимость   = доля cost заказа, пропорциональная оплате
Валовая прибыль = выручка − себестоимость
Прочие расходы  = расходы с датой в периоде
Чистая прибыль  = валовая прибыль − прочие расходы
Дебиторка       = Σ (сумма заказа − оплачено)
```

Аванс 50% признаёт половину себестоимости — прибыль не завышается.

## Архитектура

```
server.js              HTTP-сервер, REST API, авторизация, хранилище (0 зависимостей)
public/
  index.html
  styles.css           дизайн-система ПЛЕНКИН
  js/
    app.js             оболочка, роутер, поиск, быстрые действия
    store.js           состояние и API-клиент
    metrics.js         выручка, себестоимость, прибыль, воронка
    ui.js              модальные окна, формы, графики
    util.js            форматирование, иконки, статусы
    forms.js           формы сущностей
    pages/             dashboard, leads, orders, payments, clients, expenses, analytics, settings
tools/
  smoke.js             34 проверки API
  screenshot.js        скриншоты через Chrome DevTools Protocol
  reset-password.js    сброс пароля
data/                  db.json, secret.key, backups/ (в git не попадает)
```

Стек: Node.js (http, crypto, fs) + ванильный ES-модульный фронтенд. Без сборки,
без npm-зависимостей, без CDN — приложение работает офлайн и не ломается от
обновлений сторонних пакетов.

## API

Все защищённые маршруты требуют cookie сессии.

```
GET    /api/health                 проверка живости (public)
GET    /api/data                   полный снимок базы
POST   /api/auth/setup|login|logout|password
POST   /api/clients | PATCH/DELETE /api/clients/:id
POST   /api/leads   | PATCH/DELETE /api/leads/:id
POST   /api/leads/:id/convert      лид → заказ (+ клиент)
POST   /api/orders  | PATCH/DELETE /api/orders/:id
POST   /api/payments| DELETE /api/payments/:id
POST   /api/expenses| DELETE /api/expenses/:id
POST   /api/tasks   | PATCH/DELETE /api/tasks/:id
PATCH  /api/settings | POST /api/settings/rotate-token
GET    /api/export/:entity         CSV (clients, leads, orders, payments, expenses)
GET    /api/backup                 JSON-бэкап
POST   /api/import/site            импорт заявок с сайта
POST   /api/public/lead            приём заявки по X-API-Key (public, CORS)
```

### Приём заявок с сайта

```http
POST http://<host>:7788/api/public/lead
X-API-Key: <ключ из Настроек>
Content-Type: application/json

{"name":"Иван","phone":"+7 900 000-00-00","email":"mail@example.ru",
 "subject":"Заявка с сайта","message":"Комментарий","source":"Сайт"}
```

Готовый сниппет с актуальным ключом — в *Настройки → Приём заявок с сайта*.

## Безопасность

- Пароль — `scrypt` (N=16384), сессии подписаны HMAC-SHA256, cookie `HttpOnly`/`SameSite=Lax`.
- Ограничение попыток входа, проверка `Origin` для изменяющих запросов.
- CSP, `X-Frame-Options: SAMEORIGIN`, `nosniff`, защита от обхода каталога.
- Публичный приём заявок — только по ключу, ключ ротируется в настройках.
- Вся база — локальный файл; наружу ничего не уходит.

## Тесты

```bash
node tools/smoke.js http://localhost:7788      # 34 проверки API
node tools/audit-ui.js http://localhost:7788   # 33 проверки интерфейса
```

API: авторизация, CRUD всех сущностей, конвертация лида, частичные оплаты,
валидация, приём заявок по ключу, экспорт, бэкап, защита от обхода каталога.

UI: рендер всех десяти экранов, отсутствие ошибок в консоли, сценарии
«лид → заказ», «оплата», «расход», «настройки», поиск, валидация формы и
мобильная вёрстка (нижняя навигация, отсутствие горизонтального скролла).

## Данные и бэкапы

- `data/db.json` — вся база, атомарная запись через временный файл.
- `data/backups/db-ГГГГ-ММ-ДД.json` — ежедневная копия, хранятся 30 последних.
- Кнопка «Скачать бэкап» в настройках; восстановление — заменить `db.json` при остановленном сервере.
- `data/secret.key` — ключ подписи сессий, не публикуйте его.

## Развёртывание

Подробно — [DEPLOY.md](DEPLOY.md): VPS + systemd + Caddy (HTTPS), Docker, доступ по локальной сети.

**Vercel не подходит**: у serverless-функций нет постоянного диска, база будет теряться
после cold start. Именно это ломало предыдущую версию (данные в `/tmp`).
